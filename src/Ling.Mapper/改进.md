# 📌 POP：Ling.Mapper Mapper v2 性能与健壮性改造计划

## 背景

当前 `Ling.Mapper.Mapper` 已具备：
- 基于 Expression Tree 的高性能映射
- wrapper（Func<object, object?>）统一运行路径
- 枚举 / Nullable / 集合 / 复杂对象映射
- Source Generator 预留入口

但仍存在 **工程级短板**：
- 某些边界场景会直接运行时崩溃
- 映射热路径存在可消除的性能浪费
- 代码体量已接近 JIT / AOT 风险阈值
- 尚未为 v3（SourceGen / NativeAOT）做好结构准备

本 POP 用于指导 Agent **在不破坏现有 API 的前提下**完成 v2 重构。

---

## 🎯 总体目标

> 在 **不引入 AutoMapper 复杂度、不修改公开接口** 的前提下，  
> 将 Mapper 提升为 **工程级、可长期维护、Source Generator 友好** 的 v2 实现。

---

## 一、改造范围约束（必须遵守）

### ✅ 允许修改
- `Mapper` 内部实现
- `CompileMapper`
- `MapCollectionInternal`
- `ConvertSimpleType`
- 新增 `private / internal` helper、缓存结构、上下文对象

### ❌ 禁止修改
- `IMapper` 接口
- 任何 public API / public 行为
- Ignore / Rename / ForMember 的语义
- 不得引入第三方库

---
